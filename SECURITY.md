# Security Policy

## Security Model

HoneyAgent is an active cyber deception framework. It creates decoy credentials intended to look real to unauthorized threat actors and automated LLM exfiltration tools.

### Safe by Design
- **Non-Functional Credentials**: Decoys generated by HoneyAgent (such as AWS keys or PostgreSQL strings) do not confer access to real infrastructure; they only resolve to HoneyAgent's own tripwire traps.
- **HMAC Signatures**: Every generated token ID is signed with HMAC-SHA256. Forged or arbitrary token IDs cannot be attributed to genuine internal repositories.
- **No Secret Storage**: Master secrets used to sign tokens are loaded strictly via environment variables (`HONEYAGENT_SECRET`) and are never written to repository files or incident logs.

## Reporting a Vulnerability

If you identify a security issue within HoneyAgent:
1. Do not open a public issue.
2. Submit details through private GitHub security advisories or contact the repository owner.
3. Include reproduction steps, environment details, and affected components.
